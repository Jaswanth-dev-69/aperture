Privacy-first browser automation

Nothing leaves the aperture but light.

Aperture records what you do in the browser — clicks, typing, scrolling, whole checkout flows — and replays it later. No screenshot, no keystroke, no page content is ever sent anywhere. It happens on your machine, or it doesn't happen.

Why on-device

Every other lens points at a server.

The current wave of browser agents — Claude for Chrome, OpenAI Atlas, Perplexity Comet, and a swarm of smaller tools — work by sending your screen to a server and asking a model what to do next. That's a reasonable trade for a lot of tasks. It's a bad one when the tab you're automating is a banking dashboard, a patient record, or an internal tool with your employer's data in it.

Aperture takes the other trade. It fingerprints the elements you interact with — by id, by label, by visible text, by where they sit in the page — and uses that same resilient chain to find them again later, entirely inside your browser. There's no server in the loop to send anything to, because there's no server in the loop at all.

How it works

Record once. Replay reliably.

Three things have to be true for a macro to survive a page that's changed since you recorded it — Aperture is built around exactly these three.

01

Record

Click and type on any page. Every action is captured — including the real pauses between them, and steps that span multiple pages.

02

Fingerprint, five ways

Each element is remembered by id, aria-label, visible text, its position in the page's structure, and its on-screen location — a fallback chain, not a single brittle selector.

03

Replay at 1×

Playback reproduces the actual gaps between your actions, not a fixed rhythm — and follows navigations to new pages automatically.

What's built, what's next

V1 — now

Deterministic recorder

Record, resilient selector matching, 1× replay across page navigations. No AI in the loop — the strongest possible privacy claim there is.

V2 — next

On-device vision

A small vision model running in-browser via WebGPU, as a fallback for canvas and shadow-DOM elements the deterministic path can't see.

V3 — later

Team & scale

Multi-tab orchestration, scheduled runs, and a shared macro library for teams who want this beyond a single machine.
