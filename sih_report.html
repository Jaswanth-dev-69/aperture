01 — Executive Summary

The catalog is 76% software, and most of it is government plumbing

The SIH 2026 catalog holds 226 problem statements — 172 tagged Software, 54 Hardware — across 18 themes, sponsored by 30 ministries, PSUs and companies. I pulled the full official list from sih.gov.in/sih2026PS, cross-checked it against a structured community dataset for completeness, and read every one of the 172 software statements end to end.

Two things became clear immediately. First, a large share of the catalog is unbuildable for you specifically — not because the problems aren't real, but because they depend on data or infrastructure you'll never get access to: internal Oil India drilling logs, CPSE material databases, National Cybercrime Portal case data, live coal-mine SCADA feeds, Antarctic station telemetry. These are legitimate government IT problems, not portfolio projects. Second, of what remains, most of it is a workflow CRUD app wearing an "AI-powered" label — a portal with roles, forms, approvals, and a dashboard. That's the shape of problem your brief explicitly asked me to filter out.

The candidates worth your time cluster around a different pattern: the ministry's literal ask is narrow or inaccessible, but the underlying problem is real and can be rebuilt as a better, publicly-deployable product using open data or public APIs instead of the government's private pipes. That reframe — "what would this actually look like as a modern SaaS tool anyone could use today" — is where every one of my top candidates lives.

My final recommendation departs from a straight "highest score wins" reading in one respect: I weighted fit to your stated interests (frontend engineering, browser extensions, developer tools) more heavily among near-tied candidates, because a project you're excited to keep polishing beats a marginally "more technical" one you abandon after the MVP. The full reasoning, and the two runners-up I nearly chose instead, are in Sections 7 and 12.

08 — Detailed Product Plans, Top 3

From problem statement to shippable product

🥇 Aperture — privacy-first browser automation

Product vision

A Chrome extension that lets you automate, test, and extract data from any web page without a single screenshot or DOM snapshot ever leaving your machine — the "local-first" answer to the current wave of cloud browser agents.

Target users

Developers automating repetitive web tasks, QA engineers wanting visual regression tests, privacy-conscious power users, and anyone uncomfortable sending screenshots of their banking/health/work tabs to a third-party server.

Core problem

Cloud browser agents require sending page content — often sensitive — to a server for every step. Local hardware is weaker, but modern browser ML (WebGPU, WASM, ONNX Runtime Web) has crossed the threshold where useful perception can run entirely client-side.

Core user journey
  • Install extension, open side panel on any page
  • Record a macro by performing the task once (click, type, extract)
  • Aperture generates a resilient, replayable script grounded in the DOM/accessibility tree, with on-device vision as fallback for canvas/shadow-DOM cases
  • Replay on demand or on a schedule; review a step-by-step action log before anything executes
MVP definition
  • Manifest V3 extension, macro recorder using multi-strategy DOM selectors (id → aria-label → text → visual position)
  • Side-panel UI to manage/replay macros
  • Text-only optional cloud LLM call for natural-language task parsing (never images)
Advanced features
  • On-device ViT/UI-element detector via WebGPU for canvas-heavy pages
  • WebLLM local planner for flexible multi-step task decomposition
  • "What left your device" transparency panel; macro-sharing library; Playwright-style regression mode

09 — Build Roadmap for Aperture

Three versions, three purposes

V1 is what you ship for your portfolio right now. V2 and V3 exist so the project keeps compounding instead of going stale after launch.

V1 · ~4–6 weeks

Portfolio MVP

  • Manifest V3 extension skeleton: content script, service worker, React side panel
  • Deterministic DOM/accessibility-tree grounding — no ML model yet, multi-strategy selectors (id → aria-label → text → visual position) for replay resilience
  • Macro recorder: click/type capture → replayable script
  • Side-panel macro library UI; step-by-step action log with pause/confirm before execution
  • Landing page (Next.js on Vercel) with a recorded demo GIF and a sandboxed practice page users can try instantly
  • Ship to Chrome Web Store; publish repo with README, architecture diagram, MIT license
V2 · +2–3 months

Advanced features

  • On-device vision model (quantized ViT/element-classifier, <20MB) via ONNX Runtime Web + WebGPU, for canvas/shadow-DOM pages where DOM grounding fails
  • WebLLM-based local planner for flexible natural-language task decomposition
  • Privacy transparency panel: exact log of what data, if any, ever left the device
  • Macro-sharing community library backed by a small Node/Postgres service
  • Playwright-based regression mode: record once, replay in CI as a real assertion suite
  • Published model card + latency/accuracy benchmarks (WebGPU vs. WASM fallback)
V3 · production-level

Toward a real product

  • Multi-tab, multi-step task orchestration
  • Scheduled/background automation via chrome.alarms
  • Team/enterprise controls: org-managed macro allow-lists, audit logs for compliance-conscious buyers
  • Firefox port once WebGPU support broadens
  • INT4/8 model quantization, sub-200ms perception latency budget
  • Freemium model: local features free forever, paid cloud sync/team tier
